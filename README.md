# Tibu Collector Starter

This is the official starter project for building a collector for the Tibu mobile app.

It provides a complete `CollectorPlugin` implementation that collects accounts, transactions, recurring payments, purchased items, photos, and invoices from the Tibu test website, [Maison démo](https://tests.tibudget.com).

Use this project as a starting point for your own collector. It demonstrates the main features of the Tibu Collector API and provides practical examples and utilities for common collection tasks.

## Requirements

To build the project, you need:

- JDK 21 or newer. The project targets Java 21.
- Apache Maven 3.9 or newer. Maven is the reference build system.
- Android SDK Platform 35, required to generate and validate the Android DEX output.

Set `ANDROID_HOME` to your Android SDK directory. Alternatively, you can provide the Android platform JAR directly to Maven:

```sh
mvn verify -Dandroid.jar=/path/to/android.jar
```

You can check your Java and Maven installations with:

```sh
java -version
mvn -version
```

Before modifying the project, read [AGENTS.md](AGENTS.md) for the development and coding guidelines.

## Build and test

Run the complete build with:

```sh
mvn verify
```

This compiles the collector, runs the tests, packages the collector and its dependencies, and generates Android DEX code to verify that the collector can be compiled for Android.

By default, tests use saved responses from the demo website. They do not require `tests.tibudget.com` to be available.

## Build outputs

The generated files are available in `target/`. Their names use the Maven artifact ID and version as a prefix.

| File suffix | Description |
| --- | --- |
| `.jar` | Collector classes and resources only, without runtime dependencies |
| `-jar-for-tibu.jar` | Final collector archive to upload to Tibu, including the collector, its runtime dependencies and the Tibu manifest |
| `-dex.jar` | Android DEX output generated by R8 to verify Android compatibility |
| `-jar-for-r8.jar` | Intermediate JAR containing the classes provided to R8 |

For example, if the Maven artifact is `my-collector-1.0.0`, the archive to upload to Tibu will be:

```text
target/my-collector-1.0.0-jar-for-tibu.jar
```

## Collector configuration

Before publishing a collector, review the collector properties in `pom.xml`.

In particular:

- `collector.version.code` must be an integer and must increase for every published version.
- `collector.vendor` identifies the developer or organization maintaining the collector.
- `collector.default.locale` defines the default locale of the collector resources.

Do not reuse the starter values when publishing your own collector.

## Getting started

Read [Implementing a Tibu collector](docs/getting-started.md) for the main implementation principles.

The easiest way to create a collector is to clone this repository and progressively replace the demo implementation with your own.

Start by:

1. Renaming the project, Maven artifact and Java package.
2. Replacing the starter collector metadata, icon and resources.
3. Defining the parameters required to connect to the target service.
4. Implementing authentication and data retrieval.
5. Creating accounts and collecting their transactions and related data using the Tibu Collector API.
6. Adapting the tests with saved responses from the target service.
7. Running `mvn verify` to validate the collector and its Android compatibility.

The starter implementation intentionally covers several common collector features. Keep the examples that are useful for your collector and remove the ones you do not need.

## Testing

Prefer tests based on saved HTML pages, JSON responses or other fixtures instead of relying on the remote service.

This makes tests:

- reproducible,
- faster,
- independent of network availability,
- safer for services with authentication or request limits.

Add live tests only when they provide a specific benefit that cannot be covered with saved responses.

## Before publishing

Before uploading a new version to Tibu:

1. Run `mvn verify`.
2. Make sure all tests pass.
3. Check that DEX generation succeeds.
4. Increase `collector.version.code`.
5. Check the collector metadata and resources.
6. Upload the generated `-jar-for-tibu.jar` file.

## Happy collecting!

You are now ready to build your first Tibu collector.

Start simple, use the examples provided by this starter, and add features progressively. You do not need to implement everything at once.

Every new collector helps Tibu connect to more services and gives users more control over their financial data.

Happy collecting!
